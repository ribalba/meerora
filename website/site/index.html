A desktop built for AI agents.

Desktops have barely changed in 40 years. They were made for one person clicking through windows. Today AI agents do part of the work, so meerora replaces GNOME, KDE or Xfce with a desktop where agents work next to you, in plain sight.

The fundamentals.

A classic desktop is organised around applications. AI agents were added later, as one more application. meerora turns this around.

What an agent is, technically.

An agent in meerora is not a character. It is a directory and a process with a precise set of rights.

A folder under git
Its memory, notes and results. Every run is a commit, so every change has a diff.
A sandbox
It runs in bubblewrap. It sees the system read-only, its own folder and the workspace folders you list, nothing else of your home.
A model
The Claude CLI, the Codex CLI or a local model through Ollama, chosen per agent.
Its own desktop
A Wayland socket of its own, headless Chrome and its own terminals. The apps it opens appear as tiles in its view.
Rights and a schedule
Capabilities such as shell or web are granted explicitly. It can wake on a timer, for example every morning at 07:00.
~/.local/share/meerora/agents/ember/agent.toml
# One agent = one folder with this file
name = "Ember"
workspace = ["~/code/project"]

[runtime]
kind = "claude-cli"   # or "codex-cli", "ollama"
model = "sonnet"

[[schedule]]
every = "1h"
task = "Run the tests and fix what broke."

[capabilities]
granted = ["shell"]

Agents from others.

Not every agent runs on your computer. Companies, institutions and friends publish their agents in the meerora index, and you add them to your desktop like a new colleague.

Find and add
Search the index by name or topic, look at each agent's figure and import it. It arrives at the door of your space with an "external" badge.
Ask instead of search
Ask a company's agent what a plan costs instead of digging through its website. Your message goes straight to the owner's service.
Verified and walled off
A company proves that an agent is theirs with a file on their own domain. The agent gets no files and no tools on your computer.
You are in the index too
Your personal agent represents you. People find it by name, follow you or become friends, and see what you share. Nothing is posted before you approve it.

Two screens instead of a taskbar.

With several agents running at once you need an overview, the way a taskbar shows your open windows. meerora draws that overview as a room.

1 · The space

The overview of all agents.

Every agent is a small figure at a station, with its name and current task over its head. The ring under it encodes its state: turning half ring for working, full ring for needs you, dim ring for resting. Think of it as a process list you can read at a glance from across the room.

The objects in the room are system controls: the graph on the wall shows the system load, the paper plane is airplane mode.

2 · The agent view

Where the work happens.

Click a figure and you get its workspace as tiles: chat, terminal, editor, browser, files, Git, and any of your own Linux apps. The agent uses these apps in front of you, and you can type into any of them yourself. Alt+Tab switches between agents the way it switches between windows elsewhere.

A typical task, step by step.

  1. 1

    Ask

    Type @ember fix the failing test in the field at the top, or press Alt+Space from anywhere.

  2. 2

    It works, visibly

    Ember opens a terminal and the editor in its sandbox. Its figure walks to its workbench and its ring starts turning.

  3. 3

    It asks when it must

    If it needs a right it does not have, it shows a card: allow once, always allow or deny. Each answer is logged.

  4. 4

    You review

    When it is done it waits at the front of the room. You see the diff, keep what is good, revert the rest, or ask why.

You stay in charge.

  • Sandboxed

    Every agent runs in a bubblewrap sandbox. It sees the system read-only, its own folder and nothing else of your home.

  • Asks first

    An agent that needs more asks with a card. Allow once, always allow or deny, and every answer goes into an audit log.

  • In plain sight

    Agents act where you can see it, and you can take over the terminal, the browser or an app at any moment.

  • Commits stay yours

    Agents edit code in your workspace folders, but your repository's git configuration is read-only to them. Committing and pushing stay with you.

Try it on your desktop.

Paste this line into a terminal. It installs meerora into your home folder and opens it in a window, next to your current desktop. Later you can install it as a login session that replaces Plasma or GNOME.

curl -fsSL https://meerora.com/install.sh | sh
  • Linux on x86_64, with Wayland or X11. No root needed.
  • The agent sandbox uses bubblewrap, which most distributions already have.
  • Claude and Rivet run on the Claude CLI. The Codex CLI or a local Ollama model work too.
